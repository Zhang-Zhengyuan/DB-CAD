# v3 存储链路基准（P9-2，abc_cache 语料压测）

> 2026-10-19 · 工具：`CAD_DB/backend/scripts/benchmark_v3.py` ·
> 明细：`artifacts/benchmark_v3_200.json` · 语料：ABC 数据集 STEP 模型抽样 200 件
> （D:/DBCAD/abc_cache/extracted，真实工程 CAD 模型）。

## 链路

STEP → Spatial InterOp（BRep+Assembly）→ ACIS 组件（SAT 内容寻址 + GLB +
graph 投影）→ 实体级投影写入（entity_key 内容寻址 + generation 链）→ 统计。
worker 为真 ACIS 内核（x64/Debug/dbcad_worker.exe）。

## 结果（200 模型）

| 指标 | 数值 |
|---|---|
| 成功 / 失败 | **200 / 0** |
| 组件总数 | 1311 |
| 实体投影总数 | 660,772 |
| 实体内容新增 / 共享（去重） | 260,716 / 400,056 |

由 SAT 资产承载，投影结构完整（66 万实体全部入库可查）。

## 压测暴露并修复的缺陷（诚实记录，两阶段）

**第一阶段（止血）**：STEP 产物中无面体/不可离散面曾致整模型导入失败
（8/200 失败）——先改为降级：GLB 跳过 + manifest `mesh_error` 标记，
SAT/graph（几何真相与投影）照常。

**第二阶段（根因修复，评审意见"能修则不降级"）**：
1. **线框体渲染**（`body has no faces` ×4 模型）：线框体是合法几何，v3
   本就有边折线渲染能力（P2 纯线 GLB）——根因是 `MeshExtractor::extract`
   对无面 BODY 走死路。修复：无面 BODY 收集边折线产出**纯线 GLB**
   （实测 2216 字节合法 glTF，13 实体线框完整渲染），不再是降级；
2. **退化面跳过**（`face N has no faceted mesh` ×4 模型）：facet 对
   极小/退化面返回空网格是内核离散结果——单面无网格改为**跳过该面 +
   `facesSkipped` 如实计数**（与既有 `edgesSkipped` 同语义），body 其余
   面正常渲染（实测 00000198：71 面渲染 23,644 三角、2 面跳过计数）；
   其余错误（缺法线/索引越界等）仍为显式失败。
3. `mesh_error` 降级机制保留为未知失败的**最后防线**——当前语料零触发。

修复后：**200/200 零失败、mesh_error=0**；原 8 个失败模型逐一复测全部
正常渲染（4 线框体纯线 GLB + 4 含退化面模型的其余面完整网格）。

另：压测脚本初版组件键拼接 bug（bytes+str）——与存储链路无关，已修。

## 结论

- v3 存储链路（P6 投影 + P8 内容寻址增量）在真实工程语料上**零错误**，
  v2 时代的 KNOWN-DIFF（pcurve 参数域往返偏差）在 v3 无消费方
  （反序列化器退役，见 FIDELITY_REFINEMENT_ROADMAP 头注）。
- 内容寻址收益实测：60% 实体节点跨模型共享（ABC 同族模型重复几何大量），
  存储量与写入量按内容增长而非按模型数增长——这正是"不可变组件+实体
  内容寻址"的设计目标，可作为论文实验数据。
